## What is left, by what it would gain

### 1. Crashes that end every long session (highest value, not fixed)

- **#76, #135 (and probably #65): a write to `0x0` at `victory-image+0x23cf683`**, 7.5–12 min into the opening
  mission, on any settings or profile. The title's own crash log shows its physical pool 95–96% full. This looks
  like a failed title allocation used without a check, so the HLE memory accounting (`xmem.rs`: pages not given
  back, or counted twice) is the first suspect. #135 hits the same address within seconds with
  `VICTORY_BVH_BUILDER=1` on a 32-lane card. Next step: log the pool's size over time with `VICTORY_MEMORY_MAP=1`
  and compare allocations against frees per kind.
- **#146: private memory 25 → 43 GB over 55 min, then 0.3 fps** (RX 9070 XT, 32 GB). `shared buffers 34438 MB made
  so far` points to the same family: memory that grows and is never given back.
- **#40**: Bink `memcpy` reads a reserved, never-committed page during the opening cutscene (RX 7900 XT). Video
  memory is unmapped under the decoder.
- **#16**: device removed in the prison cafeteria (RTX 5070 Ti), op 46 in ten compute pipelines.
- **#6, #64**: crashes at start on Windows 10. Both probably trace to the Agility SDK: the inbox `d3d12.dll` refuses
  the direct-heap root-signature flags (see #46 and #51, which got further with `D3D12Core.dll` 1.620.2 and
  `D3D12SDKVersion=620`). Shipping the Agility SDK exports (`D3D12SDKVersion` / `D3D12SDKPath`) from `victory.exe`
  (nothing in the tree exports them today) would likely end this class of report.

### 2. Device removal on cards other than the 7900 XTX

#11 (RX 6750 XT, 16 GB RAM), #34 (RX 6800), #46 and #51 (RX 6900 XT), #50 (Arc A770) and #124 (RTX 3070 8 GB, `no host
list for a state prelude`) all end in removal. The common factors in the measurements are `TEXTURE_NO_WAIT=1` and
memory shared with the card filling up. The new `-Safe` is the first thing to ask these reporters to rerun. Open PR #92
(16 GB PCs: windows on the card, relief on out-of-memory, adaptive list pool) targets the
`no host list for a state prelude` failure directly and is worth testing against #11 and #124.

### 3. Frame time

- **#122 (7900 XTX): textures arrive late.** About 10,000 texture slots wait at a time, against about 300 in
  myokex/victory-amd on the same machine. `TEXTURE_NO_WAIT=0` costs 380–780 ms a frame, so the fix is in the queue
  order, not in that switch. #118 proposes keeping the last valid mip after a short read. Both are worth doing
  together.
- **#56**: a slow pipeline promoted to first use bypasses the slow-build limit, so several costly driver builds
  overlap during loading. The proposal is an opt-in low-memory mode.
- **#133 (7800 XT, GPU at 100%)**: replay cannot be used to find where the card's time goes. `Barrier` is not
  recorded, 814 lists on other queues are missing, and placed resources at offset 0 of heap 3 fail. Recording
  `Barrier` and the other queues would make replay the profiling tool it is meant to be.
- **#156 (Linux)**: `WINE_CPU_TOPOLOGY` gives −3%, because Linux numbers SMT siblings differently from the title's
  masks. A README line for Linux users.
- **#110** (hardware `image_bvh_intersect_ray` on AMD), **#95** (Linux: title memory in VRAM at its own addresses),
  **#15** (BCPack on async compute), **#43** (60 fps plan) and **#38** (HLE notes): proposals that need a decision
  from the maintainer, not a fix.

### 4. Picture

- **#163: `VICTORY_PORT_CONSTANTS=1` makes every world frame black under Wine/RADV**, while `PORT_DESCRIPTORS=1` is
  fine. The port's log lines look healthy, so the difference is how Wine places the low 32-bit heap's views. Keep
  the switch off on Linux until this is understood.
- **#71, #61**: magenta canopies and cloth, and too-bright reflections, without the BVH builder. The
  resolve pass reads output that was never written. #71 points at Belobug's `VICTORY_AMBIENT_SKY`.
- **#101**: `VICTORY_FIRSTLANE_OWN=1` makes all 53 builder programs translate on 32-lane GPUs. It needs a
  wave-uniform proof before it can be on by default. With the builder off, interiors are black, so this is the
  right picture, not a luxury.
- **#75** (skin missing on an RTX 3080) is the compute-dispatch-before-its-pipeline race in draft PR #129.
- **#59 part 2**: `LAND_ECHO` breaks head skin under Proton.
- **#13**: `RELAY=2` and `CARD_STEPS>0` hand back wrong skinned meshes under vkd3d-proton. `-Safe` now avoids both.

### 5. Input

**#154 / #159**: the equipment wheel cannot be operated from the keyboard. #159 is a full mapping spec. Open PR #153
(mouse as right stick and triggers, `VICTORY_MOUSE=1`) covers most of it but links neither issue. The question #159
asks (is the wheel `RB + right stick`, or `RT + right stick`?) decides whether the triggers need a digital channel.
